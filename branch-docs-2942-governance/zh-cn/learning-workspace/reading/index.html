沉浸式阅读

沉浸式阅读把文档或媒体与对话并排放在一起。助手用 [p.N] 引用来源单元——PDF 物理页、EPUB 章节、幻灯片或抽取小节；音视频则使用 [MM:SS] 或 [H:MM:SS] 这样的转录时间戳。核实过的文档 locator 会变成链接，点击后切换素材并跳到来源；高亮引文使用 reader_goto。媒体辅导依据转录，助手无法看到视频画面。没有转录时仍能播放，但助手不能声称解答依据了其中的语音内容。

它是一种能力，不是另一个应用：Chat 能做的事，在阅读回合里一样能做。

在哪里

Section titled “在哪里”

从左侧栏的学习 → 沉浸式阅读进入（或访问 /learning/reading）。先展示合集资料库；打开合集，当前素材就在阅读助手旁展开。

阅读助手是为阅读组装的 Home 聊天界面：它直接复用消息列表、输入框、Activity 抽屉和对话大纲，不再维护独立聊天实现。只有当前素材、选区、关联对话与页面提示留在 Reading。

用 New collection 一次加入一份或多份素材，也可重开已有合集。素材显示为标签页；切换时阅读器与助手的当前来源一起切换，还能留在合集内继续添加。

素材按用户存放并以内容寻址，所以再次加入同一来源时可以复用一份抽取结果，你之前做的标记也都还在。

网页链接会被清理成已存储的快照，而不是直接渲染第三方实时页面。重新抓取会保留不可变的旧 revision；捕获的图片则通过鉴权并校验 MIME 的 asset 路由提供。即使来源网站之后改变，旧引用仍然可以复核。

支持格式PDF、EPUB（含浏览器打包的 .epub.zip 文件夹）、Word、表格、幻灯片、Markdown、文本与 HTML 文件；音频和视频文件；以及网页、YouTube 或 Bilibili 链接——不含独立图片
体积上限单个文档 200 MB
原样来源视图PDF 与 EPUB 保留来源视图；音视频使用播放器；其余格式使用可重排的抽取文本
不接受纯图片的扫描件。它会被明确拒绝并说明原因，而不是打开成一个空白阅读器——请先做 OCR，或者用带 OCR 的解析引擎把它建进知识库。

和助手一起读

Section titled “和助手一起读”

素材打开后就能直接问。导航、阅读器与助手面板可调整大小并记住宽度；聚焦助手时，对话获得更多空间，素材仍在旁边。

有三件事让回答是「有依据」而不只是「有底气」：

  • 助手用和你一样的方式给文档编址。 PDF 保留物理页，EPUB 保留书脊与章节来源，演示文稿保留幻灯片，抽取格式使用小节，媒体使用带时间戳的转录片段。每个单元都有一个 locator，每个工具都接收或返回它——只有 PDF locator 是字面页码，其余格式使用各自的来源位置。
  • 阅读回合保留完整的对话能力面。 联网搜索、代码执行、你的其他知识库都还在；那八个阅读工具是加上去的，不是替换掉的。把论文的说法和网上的说法对照一遍，是一个回合的事，不是两个。
  • 有没有依据，不取决于模型愿不愿意去读。 在模型开跑之前，DeepTutor 先拿你自己的问题在打开的文档里搜一遍，把命中的几段直接交给这一回合。弱一些的模型在原生工具调用下常常一次读取工具都不调；这样它至少从对的来源单元开始。

这个前置检索是一次普通搜索，不增加额外的 LLM 轮次。它的确定性检索行为可以直接测试。

助手具体能做什么

Section titled “助手具体能做什么”
工具用来做什么
reading_list_tabs列出当前合集里的素材，并标明当前标签页及每个来源的处理状态。
reading_switch_tab在助手读取或比较另一份来源前，切换当前素材标签页。
material_outline按格式编址的文档大纲，包含 PDF 书签与 EPUB 导航或书脊标题。
search_material在打开的这份文档里做全文检索。每条命中天然带着自己的 locator。
read_material按 locator 完整读取指定的若干单元。
view_figure图片说明不足时，通过视觉模型查看一张指定的已存储图片。
reader_goto把你的阅读器滚到某个 locator，并在那里高亮一段引文。
reader_annotate以助手身份在验证过的段落上留下高亮或批注。

检索按由廉到贵分层，并会报告是哪一层命中的，好让模型分得清逐字命中和宽松命中：先 exact，再 normalised（压掉空白、忽略标点差异，所以从 PDF 里复制出来的引文即便原文在中间换了行也能对上），最后是词项重合度排序，避免一句自然语言提问什么都搜不到。

大纲按结构跳转，把你保存的书签列在文档大纲上方，并记住上次的 locator 或 EPUB 位置。上一项/下一项控件会显示即将进入的准确单元；抽取文本则在持久化字体与配色控制旁显示当前字号比例和行宽。Reading 扩展只接收验证过的可见文本或选区，受限地返回结构化结果。

注意

即便引文没法在那个 locator 上被核实，reader_goto 也照样会滚过去——用中文问一篇英文论文时，模型给出的引文是翻译过的，永远对不上，这时候拒绝滚动只会让阅读器彻底失效。批注则保持严格：只有引文确实在那儿，标记才会被写上去。

边读边标

Section titled “边读边标”

选中一段就能高亮或加下划线，并可把批注附在这段引文上。标记有五种颜色和两种视觉样式；阅读器与对话之间的列表会按 locator（页、章、幻灯片或小节）索引全部标记。

选中一段的同时，它也成了你下一条消息的对象，所以「解释一下这个」指的就是这个，不必再把原文复述一遍。

把标记带走

Section titled “把标记带走”

从阅读器工具栏导出：

  • 带批注的 PDF——在原文件里写入真正的 PDF 批注。它在预览、Acrobat 或 Chrome 里打开时高亮都在，所以你的阅读成果离开 DeepTutor 之后依然成立。适用于保留了原始字节的文档，目前也就是 PDF。
  • Markdown——按 locator 顺序列出所有标记，每条带上它的引文和批注。所有格式都能用，也正是你真正想粘进自己笔记里的东西。

它在 DeepTutor 里的位置

Section titled “它在 DeepTutor 里的位置”
  • 阅读素材不是知识库。 它不切块、不做向量、不建索引。一份文档也就几百个单元文件，线性扫一遍是毫秒级的——而且每条命中都保留精确的来源 locator，向量库做不到这点。
  • 该用知识库的时候：你想让一个问题横跨很多文档，或者想让这些材料对书本、学习笔记本和伙伴都保持可用。该用沉浸式阅读的时候：你正在读这一份文档，并希望当前页、章、幻灯片或小节保持准确——PDF 还会保留真实物理页码。
  • 阅读对话归属于它所在的工作区。 它们在左侧栏按工作区分组；重新打开时会回到 /learning/reading/<workspaceId>/sessions/<sessionId>，让阅读器、当前素材、大纲与引用继续跟着对话，而不是落到 Home 后丢掉这些上下文。

CLI

Section titled “CLI”

这个模式在 CLI 上也能用（别名 reading 和 read），但阅读器是一个 Web 界面——CLI 回合既没有可滚动的视口，也没有可操作的选区。

参见

Section titled “参见”
  • 主页——这个能力所运行的循环
  • 知识中心——建一整个语料库的索引，而不是读一份文档

区分阅读合集与工作区

Section titled “区分阅读合集与工作区”

阅读合集属于当前内容工作区。可以创建 第三周——频谱分析，加入讲义 PDF 和相关文章，再打开某个材料，问“这一页的推导依赖哪个假设？”，或选中实际段落提问。核对回答时保留来源导航与引用。一个合集可以有多段对话，但它不是新的顶层工作区。

用收藏夹保存有用结果，在学习笔记本中写自己的总结。对视频提问前，先确认已有转录。切换媒体标签会改变当前材料，但不会让导师看见视频画面。需要循序渐进的学习路线时，可将澄清后的目标带入精通之路。
